Overview

Phantom - Secure Monitoring Agent Harness System

Phantom is a centralized security monitoring system with a Gateway + Central Agent architecture. It provides autonomous diagnostic runs, real-time threat detection, and AI-powered security analysis.

Key Features
  • Autonomous diagnostic scheduling
  • Multiple input interfaces (HTTP, CLI, Queue, File, WebSocket)
  • Rule-based anomaly detection
  • Statistical anomaly detection
  • ML-based anomaly detection
  • LLM-powered security analysis
  • Skills framework for extensible capabilities
  • Tools framework for remediation
  • Alert and approval management
  • External integrations (Slack, Teams, PagerDuty, SIEM)
Architecture
System Components
Component Location Description
Gateway gateway/ Input interfaces + Schedule Manager
Central Agent central_agent/ LLM analysis loop + context + memory
Diagnostics diagnostics/ Sensor collectors
Analysis analysis/ Detection engine
Skills skills/ Agent skills
Core core/ Storage + OpenRouterClient
Data Flow
  1. Schedule Manager runs diagnostics autonomously at configured intervals
  2. Diagnostics collect sensor data (process, port, file, network, memory, etc.)
  3. Payload is created with sensor data and sent to Central Agent
  4. Central Agent updates session context, executes skills, calls LLM for analysis
  5. Detection Engine evaluates rule-based heuristics and detects anomalies
  6. Storage logs events and detections, generates reports
Diagnostic Sensors

Phantom includes multiple diagnostic sensors that collect system information at configurable intervals.

process_sensor

Collects running process information including PID, name, CPU/memory usage.

port_sensor

Monitors open TCP/UDP listening ports and connections.

file_sensor

Monitors directory for file changes (added, removed, modified).

network_sensor

Tracks network connections and external IP addresses contacted.

memory_sensor

Monitors RAM and swap memory usage percentages.

disk_io_sensor

Monitors disk usage and I/O statistics.

auth_sensor

Tracks authentication events and privilege escalation.

service_sensor

Monitors critical Windows services status.

Detection Engine

The detection engine evaluates sensor outputs against configurable thresholds and generates alerts.

Detection Types
Rule-Based

Simple heuristics comparing sensor values against thresholds.

Statistical

Detects outliers using rolling mean and standard deviation.

ML-Based

Uses Isolation Forest for anomaly detection.

Default Thresholds
Rule Threshold Description
process_count250Max running processes
open_ports50Max listening ports
file_changes100Max file changes per interval
established_connections100Max established connections
memory_percent90%Max memory usage
failed_logins5Max failed logins per interval
